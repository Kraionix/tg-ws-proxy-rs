# v2.5.10-struct-logging

The upstream **2.5.10** release, with the structured record log this fork exists for. Same console
log, same records, same `--log-dir` segments; the difference from upstream is that the lines are
rendered from records instead of being the only copy.

The version says exactly what it is: upstream 2.5.10 plus this feature, and deliberately not a
release of its own. It sorts below 2.5.10 in semver, so the tag shape is `v2.5.10-struct-logging`
and `release-version` accepts the suffix instead of demanding a bare triplet.

## What came from upstream

Everything in 2.5.5 … 2.5.10, unchanged in behaviour:

- **2.5.5** — a pinned ladder (`--pinned-upstream`, `--pinned-media-upstream`) now honours the
  `--dc-ip` cooldown: the `ws` rung steps over a cooled address while a later rung can still
  connect, and comes back for it once every rung has failed.
- **2.5.6** — a TCP connect that times out ends the hostname walk: a cold direct tier costs one
  `--ws-connect-timeout`, not two.
- **2.5.7** — when the cooldown runs out, a background probe re-tests the address instead of the
  next client. An answer clears the cooldown, another timeout starts a fresh window.
- **2.5.8** — a failed `--default-domains` fetch no longer pins the run to the five built-ins: the
  proxy serves from them and re-fetches in the background (15 s doubling to 5 min, about an hour),
  and connections accepted after a success use the full list. Pinned "tier has no … target" lines
  are DEBUG now.
- **2.5.9** — Windows 7/8 archives, and an Android Quick Settings tile. (The fork's own release
  workflow carries the same win7 rows, built with the sink.)
- **2.5.10** — with `--cf-balance`, pool spares are dialled at the `kws{N}.<zone>` record, not the
  zone apex that answers 530.

The commit-by-commit history of the upstream update is preserved: the twelve upstream commits are
in this branch as themselves, not squashed into one.

## What is new in the records

Three additions, all for behaviour that upstream only narrates on the console:

- **`cooldown_reprobe`** (info) — a cooled rung dialled again because every other pinned rung
  failed. The default ladder says the same thing as the step back up from TCP; a pin has no such
  step, so it gets an event of its own rather than a `tier_fallback` naming a rung it never took.
- **`domain_refetch`** (debug / info / warn) — each background retry of the domain list, the
  success that swaps the list in, and the give-up after about an hour.
- **`probe_result` with `kind = ip_fail`** — the background re-test of a cooled `--dc-ip`: how
  long it took and what it found. It runs outside any session, so it is emitted with
  `conn_id = 0`, and its outcome also lands as the `cooldown_cleared` / `cooldown_armed` record
  the default ladder already uses.

The startup line for a built-in domain list now says `re-fetching in the background`, because the
fallback is no longer permanent.

## Compatibility

The wire format is additive: `SCHEMA_VERSION` stays 2, the event count goes 22 → 24, and the
segment header fingerprint moves. This build reads segments written by 2.5.4-struct-logging
unchanged. The reverse is not true: a 2.5.4-struct-logging binary refuses a segment this build
wrote, the way it refuses any schema it does not know. Keep the new binary for reading the new
segments.

## What it costs

Nothing on the routing path. The probe is one background connection attempt per cooled address per
window, at most two `--ws-connect-timeout`s long; the domain retry is at most fifteen HTTPS
requests over the first hour, and only after a failed startup fetch. No new flags, no new
dependencies, and the on-disk sink stays behind `log-disk` exactly as before.
