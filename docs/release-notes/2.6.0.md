# v2.6.0

The proxy can write a **structured event log** beside the text log it has always written: one record
per event, batched into one segment file per UTC day, on a directory you choose. It is off by default —
without `--log-dir` the banner, the console output and `--log-file` are byte-for-byte what they were
in 2.5.4.

## Why

The console log records the decision the ladder made; it cannot record the inputs, and it cannot be
counted. "Telegram dropped again" is answerable only if the log says *which rung carried the session,
what class of failure ended the previous one, how long that took, and which cooldown it armed* — and
those are exactly the fields a text line has no room for. The structured sink is not a replacement for
the text log: it is the second sink that can be read back by a program instead of by an eye.

## What's new

- **`--log-dir` and the `--log-*` family** — `--log-level`, `--log-category`, `--log-retention`,
  `--log-compress`, `--log-durability`, `--log-flush-interval`, `--log-batch-max`,
  `--log-flush-on-warn`. Every flag has its `TG_LOG_*` environment variable, like the rest of the CLI.
- **Seventeen events** across ten categories, from `session_opened` / `tier_attempt` /
  `tier_fallback` / `cooldown_armed` to the pool's `pool_hit` / `pool_miss` / `pool_refill`, the
  connectivity probes (`probe_result`), the descriptor budget (`fd_snapshot`) and the process's own
  `startup_summary`. Levels are a floor and can be raised per category.
- **Day segments in redb**, with retention by file name, `zstd-l1` compression, and a choice of
  durability. A segment written by one version reads back in a later one: the schema is fixed by
  field tag, not by code layout.
- **A filesystem gate.** `--log-dir` on a FAT-family mount is refused at startup instead of being
  allowed to corrupt a segment later; the banner names the filesystem it actually landed on, and warns
  when that filesystem is `tmpfs`.
- **The banner estimates the cost** — `~44 B/record · ~1 record per client connection (~4 at debug)`,
  with a per-week projection — so the decision to keep the log is made with numbers rather than hope.
- **Three fixes found by reading the log back**: the Cloudflare edge cooldowns are now recorded (they
  were the one failure memory that never reached the log), the `--check` probes report the same failure
  classes as the ladder instead of a generic error, and the sink no longer records steps the ladder and
  the pool never took.
- **`SIGTERM` is handled.** It used to kill the process; now the process stops, drains the writer and
  exits `0`, and a second signal exits immediately for the case where stopping hangs. On OpenWrt this
  is also what makes `stop` quick: the init script's own comment documented the old behaviour — the
  child had to be killed with `SIGKILL` after a three-second wait.

## What it costs

| Target | 2.5.4 | 2.6.0 | 2.6.0 with `--features log-zstd` |
|---|---|---|---|
| `x86_64-unknown-linux-musl` | 4 481 040 B | 5 646 664 B (+26 %) | 6 200 360 B |
| `aarch64-unknown-linux-musl` | — | 4 792 928 B | 5 317 216 B |

The zstd codec is half a megabyte of that, so it stays behind an off-by-default feature: the release
workflow builds it in for the musl targets (aarch64, x86_64), the Apple targets (both architectures and
the universal build) and `x86_64-pc-windows-gnu`, and leaves it out of the armv7 and MIPS targets.
Without the feature, `--log-compress` offers `none` alone, and a compressed segment cannot be read by
that build.

Writing the log costs a few hundred kilobytes a week in *record* bytes: a record is ~44 B, a client
connection writes about one of them at `info` and about four at `debug`, and an idle process writes one
descriptor snapshot a minute. What the **medium** sees is larger, and worth knowing before pointing this
at a cheap stick: every flush window that carries a record ends in one `redb` commit, and a commit
dirties pages rather than records. Measured on a router writing `debug` logs to a USB stick on f2fs —
51 commits, 328 records and 98 client sessions in seven minutes — the device took **916 KiB**, about
**18 KB per commit**, against ~25 B/s of record payload. An idle proxy commits nothing, so
`--log-flush-interval` is the lever: fewer, fuller commits in exchange for a larger crash window. A
4 GB stick absorbs the measured rate for years; a router's own flash may not be the place for it.

Durability has two windows, and the flags name both. A record waits in memory for at most
`--log-flush-interval` (2 s by default) before it is committed, so a process that dies — `kill -9`,
the OOM killer — takes at most that with it. A power cut takes everything committed but not synced,
which under the default `eventual` is at most 30 s; `--log-durability immediate` closes that window
at the price of one `fsync` per flush. A clean stop is complete in both modes. `--log-flush-on-warn`
pushes warnings and errors out immediately. The `--log-flush-interval` help text no longer claims to
bound the power-cut window, which it never did.

## Upgrading notes

- Nothing changes for an existing installation that does not pass `--log-dir`.
- Points the sink at a filesystem that can hold a lock-protected database — `ext4`, `xfs`, `btrfs`,
  `f2fs`, `tmpfs`, `overlayfs` or `ubifs`. FAT-family mounts are refused at startup with a message
  naming the filesystem.
- **OpenWrt/`ujail`:** the log directory has to be staged into the jail (`procd_append_param command -w
  /path`), and it must exist before the jail is built. Two traps: the jail contains no external
  commands, so a wrapper that shells out to `cat` or `grep` dies with exit 127 and procd turns that
  into a crash loop; and `ujail` does not forward the stop signal to the jailed child, so the init
  script has to signal the child as well.
- Reading a segment needs a build with the same codec: `TG_DUMP_DIR=… TG_DUMP_DATE=… cargo test
  --features log-zstd --lib dump_segment -- --ignored --nocapture`. There is no CLI reader by design —
  [docs/Logging.md](../Logging.md) documents the details.
