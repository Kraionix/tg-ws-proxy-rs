# v2.6.0

The proxy writes **one record per event**, and the text log you read is rendered from those records:
the console is a projection of the same stream the segment files hold, not a second description of it.
The record pipeline always runs; `--log-dir` decides whether the records are also stored on disk, and
without it nothing is written anywhere.

The version is **2.6.0**: upstream 2.5.4 plus a feature that adds a new on-disk format and changes the
CLI, which is a minor bump rather than a patch. `package.metadata.android.version_code` moves with it
(`206000`), and the release workflow reads the notes by that number — this file, headed `# v2.6.0` —
so the two cannot drift apart.

## Why

The console log records the decision the ladder made; it cannot record the inputs, and it cannot be
counted. "Telegram dropped again" is answerable only if the log says *which rung carried the session,
what class of failure ended the previous one, how long that took, and which cooldown it armed* — and
those are exactly the fields a text line has no room for. The record is the fact; the line is how it
is read, and a segment is how it is kept.

## The text log is now a projection of the records

The rework that closed the loop between the two logs. What a person reads and what a program reads can
no longer disagree, because there is only one of them:

- **`--text-log [stderr|stdout|off|PATH]`** (`TG_TEXT_LOG`) chooses where the rendered text goes,
  default `stderr`. A path is appended to, never truncated.
- **`--text-level`** (`TG_TEXT_LEVEL`) is the text's own floor, and **`--ring-level`** /
  **`--ring-capacity`** (64…4096, default 512) configure the RAM ring behind `SIGUSR1`. The three
  consumers — segment, text, ring — filter independently; a record is built if any of them wants it.
- **The pipeline no longer needs a disk.** Without `--log-dir` the sink keeps nothing and the records
  still reach the text log and the ring, so `--text-log /var/log/tg-ws-proxy.log` alone is a complete
  configuration.
- **The banner moved to stdout and is printed unconditionally.** It carries the secret and the
  `tg://` links, and it is no longer something a log level can silence: `--quiet` and `--text-log off`
  do not touch it.
- **`--log-file` is gone** — `--text-log PATH` writes the same text, and an old command line fails at
  parse time instead of logging to stderr while the operator watches an empty file. `--verbose` and
  `--quiet` still work as hidden aliases for `--text-level debug` and `--text-log off`, because the
  Android app and existing init scripts pass them.
- **Nothing of the proxy's own goes through `tracing` any more.** `rustls` and `tungstenite` still do:
  those lines appear only if `RUST_LOG` asks for them, always in stderr, always prefixed with
  `tg-ws-proxy: ` so they cannot be mistaken for a record.
- **A line that is not a record says so.** The log's own failures (a full disk, a segment held by
  another process), the second stop signal and the configuration warnings are `tg-ws-proxy:` lines in
  stderr; the inbound handshakes that are refused before a session exists follow `--text-level`, so a
  port scanner still leaves nothing behind at the default `info`.
- **`--check` keeps the text log off**, whatever the flags say: its report is the product of the mode.

## What's new (the structured sink)

- **`--log-dir` and the `--log-*` family** — `--log-level`, `--log-category`, `--log-retention`,
  `--log-compress`, `--log-durability`, `--log-flush-interval`, `--log-batch-max`,
  `--log-flush-on-warn`. Every flag has its `TG_LOG_*` environment variable, like the rest of the CLI.
- **Twenty-two events** across ten categories, from `session_opened` / `tier_attempt` /
  `tier_fallback` / `cooldown_armed` to the pool's `pool_hit` / `pool_miss` / `pool_refill`, the
  connectivity probes (`probe_result`), the descriptor budget (`fd_snapshot`) and the process's own
  `startup_summary`. Levels are a floor and can be raised per category.
- **Day segments in redb**, with retention by file name, `zstd-l1` compression, and a choice of
  durability. A segment written by one version reads back in a later one: the schema is fixed by
  field tag, not by code layout.
- **A filesystem gate.** `--log-dir` on a FAT-family mount is refused at startup instead of being
  allowed to corrupt a segment later; the banner names the filesystem it actually landed on, and warns
  when that filesystem is `tmpfs`.
- **The banner estimates the cost** — `~44 B/record · ~1 record per client connection (~4 at debug)`,
  with a per-week projection — so the decision to keep the log is made with numbers rather than hope.
- **Three fixes found by reading the log back**: the Cloudflare edge cooldowns are now recorded (they
  were the one failure memory that never reached the log), the `--check` probes report the same failure
  classes as the ladder instead of a generic error, and the sink no longer records steps the ladder and
  the pool never took.
- **`SIGTERM` is handled.** It used to kill the process; now the process stops, drains the writer and
  exits `0`, and a second signal exits immediately for the case where stopping hangs. On OpenWrt this
  is also what makes `stop` quick: the init script's own comment documented the old behaviour — the
  child had to be killed with `SIGKILL` after a three-second wait.

## What it costs

| Target | upstream 2.5.4 | this build | this build with `--features log-zstd` |
|---|---|---|---|
| `x86_64-unknown-linux-musl` | 4 616 896 B | 5 728 448 B (+24 %) | 6 277 312 B (+36 %) |
| `aarch64-unknown-linux-musl` | 3 862 600 B | 4 773 464 B (+24 %) | 5 228 120 B (+35 %) |

Every row is built from one profile and one toolchain: the same source built for
`x86_64-unknown-linux-gnu` is ~135 KB smaller than its musl twin, so a gnu baseline against a musl build
would overstate the cost by about four points. The zstd codec is half a megabyte of that, so it stays
behind an off-by-default feature: the release workflow builds it in for the musl targets
(aarch64, x86_64), the Apple targets (both architectures and the universal build) and
`x86_64-pc-windows-gnu`, and leaves it out of the armv7 and MIPS targets.
Without the feature, `--log-compress` offers `none` alone, and a compressed segment cannot be read by
that build.

Writing the log costs a few hundred kilobytes a week in *record* bytes: a record is ~44 B, a client
connection writes about one of them at `info` and about four at `debug`, and an idle process writes one
descriptor snapshot a minute. What the **medium** sees is larger, and worth knowing before pointing this
at a cheap stick: every flush window that carries a record ends in one `redb` commit, and a commit
dirties pages rather than records. Measured on a router writing `debug` logs to a USB stick on f2fs —
51 commits, 328 records and 98 client sessions in seven minutes — the device took **916 KiB**, about
**18 KB per commit**, against ~25 B/s of record payload. An idle proxy commits nothing, so
`--log-flush-interval` is the lever: fewer, fuller commits in exchange for a larger crash window. A
4 GB stick absorbs the measured rate for years; a router's own flash may not be the place for it.

Durability has two windows, and the flags name both. A record waits in memory for at most
`--log-flush-interval` (2 s by default) before it is committed, so a process that dies — `kill -9`,
the OOM killer — takes at most that with it. A power cut takes everything committed but not synced,
which under the default `eventual` is at most 30 s; `--log-durability immediate` closes that window
at the price of one `fsync` per flush. A clean stop is complete in both modes. `--log-flush-on-warn`
pushes warnings and errors out immediately. The `--log-flush-interval` help text no longer claims to
bound the power-cut window, which it never did.

## Upgrading notes

- **A console-only installation changes.** The records are rendered to stderr by default, which is
  what the old `tracing` lines went to, so a run without flags looks much the same — with two
  differences: the banner is now on stdout (redirect both if you collect one file), and `--log-file`
  no longer exists. Replace `--log-file PATH`/`TG_LOG_FILE` with `--text-log PATH`/`TG_TEXT_LOG`.
  `--verbose` and `--quiet` keep working.
- **`RUST_LOG` no longer sets the console's level** — it only turns on other crates' lines, which are
  prefixed `tg-ws-proxy: `. Use `--text-level`/`TG_TEXT_LEVEL` for the proxy's own output.
- Reading a segment written **before** this build: the schema changed (new events, new fields,
  `SCHEMA_VERSION` 2), and today's file is refused at startup rather than appended to. Move the old day
  files out of the log directory before deploying this build.
- Nothing changes for an existing installation that does not pass `--log-dir`.
- Points the sink at a filesystem that can hold a lock-protected database — `ext4`, `xfs`, `btrfs`,
  `f2fs`, `tmpfs`, `overlayfs` or `ubifs`. FAT-family mounts are refused at startup with a message
  naming the filesystem.
- **OpenWrt/`ujail`:** the log directory has to be staged into the jail (`procd_append_param command -w
  /path`), and it must exist before the jail is built. Two traps: the jail contains no external
  commands, so a wrapper that shells out to `cat` or `grep` dies with exit 127 and procd turns that
  into a crash loop; and `ujail` does not forward the stop signal to the jailed child, so the init
  script has to signal the child as well.
- Reading a segment is the binary's own job: `tg-ws-proxy probe-segment <dir>` summarises each day file
  (size, SHA-256, batches, records, connections, events), and `tg-ws-proxy dump-segment <dir>
  [--date D] [--out FILE] [--records-only]` prints the records as JSON Lines. Reading a segment written
  with `zstd-l1` needs a build with the same codec, `--features log-zstd`. The reader makes a private
  copy and reads that, so a read leaves the archive's bytes — and its hash — exactly as they were;
  [docs/Logging.md](../Logging.md) documents the details.
